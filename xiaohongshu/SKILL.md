# Xiaohongshu Copywriting Skill

产出两样东西：**可直接粘贴的文案**（标题 + 正文 + 标签）和**配套竖版图片**。

## Core Rules

1. **标题 ≤ 20 字**（含空格、emoji、符号）。给 2–3 个选项。
2. **正文 ≤ 1000 字**。
   本技能默认按 **UTF-16 code unit** 做长度检查：换行算 1，多数 emoji 算 2。
   20/1000 是随包检查器的默认上限；实际发布以当前平台提示及用户要求为准。
   **绝不靠目测估算**。写完必须跑：
   ```bash
   python <skill目录>/scripts/count.py body.txt
   ```
   超限就删内容再测，直到通过；目标留 30–50 字余量。报给用户的字数必须是脚本实测值。
3. **复制块内禁止 markdown**：不得出现 `**`、`*`、`_`、`###`、`|` 表格。
4. **emoji 与列表**：段落/小节以 emoji 起头（💡 🚀 🛠 📍 💥 ⚡️ 🤔 📚）；列表用 `1、` `2、` 或 `📍` `📌`，不用 `-` / `*`。
5. **标签**：放正文末尾。宁可少而准，删掉 #人工智能 这类过泛的词，它们不带来精准流量。
6. **时间基线**：使用当前真实日期；论文年份按原文填写，不把旧工作改写成今年发布。

## 写作要点

- **不要制造虚假时效性**。除非确认是新发布，禁止用「又刷新了」「刚发布」「最新」。
  「至今榜一」「依然是 SOTA」同样需要最新证据。先确认发布时间与比较设置，
  拿不准就用中性说法，不承诺排名或流量。
- **论文原链接**：论文介绍类文案必须在末尾附上完整论文原链接，放在标签之后，格式为「论文原链接：https://…」。优先使用已核实的 arXiv 摘要页、会议或出版社官方论文页；不要用项目仓库或二手解读替代，不得猜测链接。最终字数检查必须包含标签和链接。URL 内的下划线等字符不受复制块 markdown 禁令限制。
- **其他引流链接**：非论文原链接的项目或推广链接，默认不在正文放完整 URL。
  正文写「GitHub 搜 用户名，仓库 xxx」，完整链接放**评论区置顶**或**个人简介**，并在交付时提醒用户。
- **研究启发要具体**：技术论文解析需要回答「这对我们意味着什么、可以如何利用、怎样验证」，不能只补一句赞叹或泛泛的未来方向。区分论文已验证的结果、个人判断和待验证设想；至少把最有价值的一个方向写成具体做法与验证问题。写论文解析或用户要求更多思考时，读 [references/paper-thinking.md](references/paper-thinking.md)。
- **短板要写**。技术类读者吃这套，也降低被质疑的风险。
- **压字数时的删除优先级**：图片已表达的内容 > 次要技术细节 > 泛标签 > 修饰词。核心数据和主线论点一个都不能删。

## 封面选题

决定点击率的不是排版，是**封面选了哪个故事**。默认行为很容易变成「拿正文第一节当封面」，而第一节往往是统计节 —— 那是筛选流程的副产品，读者不关心某个榜单这周有没有更新。

从正文各节里挑，优先级从高到低：

1、**威胁读者已有认知** ——「把时钟打开，零样本方法集体掉点」（暗示你论文里的 SOTA 可能是同步仿真给的）
2、**影响读者的方向选择** ——「50 项新工作里，地面导航只剩 6 项」
3、**给出能直接用的方法** ——「缺动作标注，但不缺视频」
4、统计与流程 ——「53 条里只有 1 项报了 R2R-CE」（几乎永远不该当封面）

三条硬约束：

📍 **用判断，别用数数**。「只有 1 项」是数数结果，没人反驳也没人评论；「重心正在离开导航」是判断，会引发认同或反驳，两者都是互动。
📍 **不用否定式盘点当封面**。「本周空白」「不具备条件」传达的是「这周没什么好东西」，等于劝人别点。要点里也尽量避免连续否定。
📍 **主数字必须和标题同向、且可核验**。标题说「集体掉点」却配 `+11%`，读者会以为是好消息。取自摘要、未核验原文的数字不要放进巨型数字位 —— 那个位置在缩略图里最显眼，出错代价最大。

## 配图生成

小红书竖版 **1080×1440（3:4）**，首图即封面。生成前读 [references/card-design.md](references/card-design.md)，先确定每页要回答的问题和视觉主体，再选模板。目标是封面容易理解、内页值得继续读；吸引力改进需要用发布数据验证，不承诺流量。

用配置驱动脚本生成；`<skill目录>` 是当前 SKILL.md 所在目录：

```bash
python <skill目录>/scripts/make_cards.py config.json
```

先读 [QUICKSTART.md](QUICKSTART.md) 安装依赖。可运行的三页演示见 `examples/demo.json`；
演示配图为仓库原创示意图，图表数据是虚构值，不代表平台指标或实验结果。
配置中的相对路径以配置文件所在目录为基准；字体、署名和引流文案均可自行设置。

**三种页面类型**

| type | 用途 | 关键字段 |
|---|---|---|
| `cover` | 封面：一个问题或结论 + 一幅主体图，或一个有意义的主数字；卖点按需精简 | `line1` `line2` `metric` `points` `footer`；插图版用 `hero` `hero_label` `max_h` |
| `figure` | 引用原图 + 要点，可插一个大数字强调块 | `image` `crop_bottom` `max_h` `stat` `bullets` |
| `bar` | 自绘横向对比条形图 | `series` `legend` `xlim` `bullets` |

`bullets` 里以 `*` 开头的行会被加粗高亮。

**必须注意的几点**

- **按实际图像裁图注**：用 `crop_bottom` 去掉重复的英文 Figure caption，先查看原图，不套固定裁剪比例；保留坐标、图例、方法标注和其他有效信息。
- **留白**：`bullets` 会在图片底部到 CTA 条之间自动垂直居中并拉开行距。
  图片太扁时可放大关键局部或更换构图；只有数字确实支撑本页结论时才加 `stat`，不为填空重复数字或堆文字。
- **溢出**：`bar` 页的图表高度由 `figsize` 决定，图表 + 要点会挤压 CTA 条。
  4 行要点配 `figsize` 高度不超过 6.0；渲染后用当前环境的图片查看工具确认没重叠，必要时缩短文字或拆页。
- **底部 CTA 条**：新图组默认仅在最后一页集中展示延伸入口，其他页保留简洁署名与来源。全局 `cta` 提供默认值；页面 `cta: false` 隐藏引流条，页面 `cta: {"title": "…", "sub": "…"}` 设置该页内容。也可以不设全局 `cta`，只在末页设置。用户指定每页引流时遵循其选择。
- 原图从本地仓库读（`src_root` + `image` 相对路径），比抓网页快且清晰。
- **没有原图时要自己画图解，不能把要点文字塞进方框当配图**（那样整组图看起来全是字）。
  每页选一种能表达机制的图：场景 / 平面图、做法对比流程、输入→输出例子、闭环框图、示意坐标图；
  图里的内容应是要点没说的，编造的数值一律标「示意，非实测」。
  做法：写 992 宽的 SVG（正文字号 ≥ 24px），用 headless Chrome 以 2x 截图成 PNG，再交给 `figure` / `hero`。
  简单图解也可用本机绘图库生成，再通过 `figure` / `hero` 引用；不依赖特定个人仓库。

**每次生成后都要逐张查看原尺寸和手机尺寸成图**。配置加 `"previews": true`，脚本会在 `_previews/` 输出 240px 宽首图、360px 宽各页和总览图；这是阅读检查尺寸，不是平台规格。封面大标题和主数字必须自解释，不能依赖小字才能看懂。检查封面缩小后能否识别主题、内页能否读清关键标签、文字重叠、裁剪损失和 CTA 遮挡。必要时改内容或拆页，不要仅靠缩小字体。预览图不混入发布图片。

## Execution Workflow

1. 读懂源内容，抽出核心结果、机制、评测边界与可落实的研究启发，分清已验证结果和提出的设想。
2. 起 2–3 个标题（各 ≤ 20 字）。
3. 写正文，**跑 count.py 验证 ≤ 1000**，超了就删再测。
4. 加标签；论文介绍类在末尾追加「论文原链接：完整 URL」。对最终完整正文（含标签和链接）再次跑 count.py，验证 ≤ 1000，超限就精简介绍后重测。
5. 用代码块给出文案，方便一键复制。
6. 生成配图：先按「封面选题」确定封面故事 → 读配图设计参考 → 按内容分镜 → 写 config.json（开启 previews）→ 跑 make_cards.py → 查看原图与缩略预览 → 修 → 交付。
7. 交付时说明：图片发布顺序、最终完整正文实测字数。论文介绍类的论文原链接必须已附在文案末尾；其他推广链接按上述引流规则处理。
