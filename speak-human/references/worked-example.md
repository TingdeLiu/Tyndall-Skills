# 完整示例：术语原文 → 大白话

## 原话（用户看不懂的那一条）

> 把 `/camera/image_raw` 的 QoS 从 RELIABLE 改成 BEST_EFFORT，depth 设为 1。
> 当前 DDS 层因为订阅端处理速度跟不上发布频率，队列持续积压，导致下游 tf 变换的
> 时间戳滞后约 400ms，进而让局部规划器基于过期位姿做决策，出现绕圈行为。

---

## 重讲之后

**一句话：** 机器人在拿 0.4 秒前的旧画面做决定，所以老绕圈；改个设置，让它宁可丢几张图，也只看最新的那张。

**打个比方——传送带上的照片：**

- 摄像头 = 一个不停拍照的人，每秒拍 30 张，拍完往传送带上放。
- 处理画面的模型 = 传送带尽头看照片的人，他每秒只看得完 10 张。
- 现在的设置（`RELIABLE`，"一张都不能丢"）= 规定每张照片都必须被看到。于是传送带上越堆越多，他手里那张已经是 0.4 秒前拍的了。
- 机器人照着 0.4 秒前的画面决定往哪走，等它真走到，世界早变了 → 于是原地绕圈。
- 改法（`BEST_EFFORT` + `depth=1`，"只留最新一张"）= 不再要求每张都看，传送带上只放得下一张，新照片直接把旧的盖掉 → 他手里永远是刚拍的。

```
改之前（一张都不能丢）
 摄像头 ─▶ [旧][旧][旧][旧][新] ─▶ 模型拿到的是最左边那张
                                     （0.4 秒前拍的）

改之后（只留最新一张）
 摄像头 ─▶ [    新    ] ─▶ 模型拿到的就是刚拍的
             旧的直接被盖掉
```

**具体到你这件事：**

- 要动的是**发消息和收消息两边**的设置，两边不一样会直接连不上，只改一边等于没改。
- 改完应该看到：绕圈没了；画面偶尔跳一下是正常的，那就是被盖掉的旧照片。
- **什么时候不该这么改**：如果这一路图像是要录下来做离线评测的，丢帧 = 数据缺了一块。那种情况要保住"一张都不能丢"，改成让模型跑快点，或者让摄像头少拍点。

**术语对照表**

| 刚才说的 | 其实就是 |
| --- | --- |
| QoS | 收发消息的规矩：丢不丢得起、排队能排几条 |
| RELIABLE | 一张都不能丢，丢了要重发 |
| BEST_EFFORT | 尽力送到就行，丢了拉倒 |
| depth = 1 | 排队的位置只有一个，新的直接盖掉旧的 |
| DDS | ROS 2 底下真正负责搬消息的那套东西 |
| 队列积压 | 传送带上堆成一摞，越堆越多 |
| tf 时间戳滞后 400ms | "我现在在哪"这个信息，晚了 0.4 秒 |
| 位姿 | 机器人此刻在哪、朝着哪 |
| 局部规划器 | 决定下一小步往哪挪的那段代码 |

> 哪一块还是糊的？点出来，我只把那一块再拆细。

---

## 这个例子踩中了哪几条规矩

- 一句话结论放最前，40 字以内，先说「拿旧画面做决定」这个因果，不是先说改哪个参数。
- **一个类比撑到底**：传送带。摄像头、模型、两种设置、跳帧，全都在同一个比方里有对应角色，中途没换成别的比喻。
- `400ms` 换成了「0.4 秒前拍的」，并且和「等它走到世界早变了」绑在一起——数字有了参照物。
- 图只画了「前 / 后」两种队列，因为这里的核心差别就是队列长度。没有硬凑分层图。
- 「两边都要改」「什么时候不该这么改」这两条**是原话里没有但必须补的前提和风险**——简化不等于删掉坑。
- 术语表里每个词都在正文出现过，没有凑数的百科条目。
