# ASCII 图模板

## 先选型

原文里出现什么 → 用哪张图。对不上号就别画。

| 原文里有 | 用哪张 |
| --- | --- |
| A 之后 B，B 之后 C | 1 流水线 |
| 上层不用管下层怎么干 | 2 分层 |
| 改之前 / 改之后、有 / 没有 | 3 前后对比 |
| 一直转、反复重来 | 4 闭环 |
| 第几毫秒发生了什么 | 5 时间线 |
| 谁占大头、瓶颈在哪 | 6 占比 |
| 一件事拆成几件小事 | 7 包含关系 |
| 快和便宜不能全都要 | 8 取舍 |
| 三个方案摆在面前挑一个 | 9 选项对比 |
| 先问自己一个问题，答案决定下一步 | 10 决策树 |

一段内容里有几个结构就画几张，别硬挤成一张。裁决类的内容（选 A 还是 B），
9 和 10 至少出一张。

## 通用规矩

1. **总宽度 ≤ 60 列**，超了会在终端折行，图就废了。
2. **一个汉字 = 2 列，中文标点（，。（）「」）也 = 2 列**，半角空格和英文字母 = 1 列。对齐按列数算，不是按字数算。
3. **同一行里的几个框，框内汉字数要一样多**，不够的用半角空格补。数不清就用「无边框」写法（模板 1 上半部分），完全不会歪。
4. **带边框、要对齐的图，箭头只用 ASCII**：`-->`、`>`、`v`、`|`。`▶ ▼ ▲` 在一部分终端里占 2 列，会把整张图挤歪。无边框的图（不需要对齐）随便用 `▶ ▼`。
5. **箭头上下要写「发生了什么」**，光画箭头等于没画。
6. **一个框里只放一个名词**，超过 6 个汉字就换个说法。
7. **不要用 emoji 当框线或图元**，等宽字体里宽度不统一，一定歪。
8. **图不是装饰**：去掉这张图如果不影响理解，就删掉它。

## 1. 流水线 / 流程

无边框版（推荐，永远不会歪）：

```
摄像头 ──▶ 认路模型 ──▶ 算速度 ──▶ 轮子
 30帧/秒     0.2秒/次     每秒10次
```

带框版（同一行汉字数必须相同）：

```
┌────────┐   ┌────────┐   ┌────────┐
│ 摄像头 │-->│ 找路子 │-->│  轮子  │
└────────┘   └────────┘   └────────┘
```

## 2. 分层

```
┌──────────────────────────────┐
│  你说的话（去厨房）          │ ← 最上层，人管的
├──────────────────────────────┤
│  拆成一串小目标              │
├──────────────────────────────┤
│  每一步往哪走                │
├──────────────────────────────┤
│  轮子转多快                  │ ← 最底层，机器管的
└──────────────────────────────┘
```

上面的东西不用管下面怎么干活，这就是「分层」的意思——写解释时要把这句话讲出来。

## 3. 前后对比

```
        以前                改完以后
┌──────────────────┐   ┌──────────────────┐
│ 每帧都存下来     │   │ 只存关键帧       │
│ 内存越吃越多     │   │ 内存稳住不涨     │
│ 跑 10 分钟就崩   │   │ 跑一整天没事     │
└──────────────────┘   └──────────────────┘
```

## 4. 闭环 / 反复循环

```
   ┌─────────────────────────────────┐
   │                                 │
   v                                 │
 看一眼 ──> 想下一步 ──> 走一步 ─────┘

        这一圈每秒转 10 遍
```

## 5. 时间线

```
0 秒        0.2 秒      0.5 秒       1 秒
├───────────┼───────────┼───────────┤
拍到画面   模型算完   命令发出去   轮子动
```

刻度标签对齐到大致位置就行，不用逐列死抠。

## 6. 占比 / 谁是大头

```
模型推理  ████████████████░░░░  78%  ← 大头在这
数据搬运  ███░░░░░░░░░░░░░░░░░  15%
其它      ██░░░░░░░░░░░░░░░░░░   7%
```

条形固定 20 格，一格 = 5%。左边标签补空格到等宽。

## 7. 包含关系 / 拆解

```
一次导航任务
├─ 听懂指令
│  ├─ 把话拆成词
│  └─ 找出目标物体
├─ 规划路线
│  └─ 避开障碍
└─ 走过去
   └─ 到了就停
```

## 8. 取舍（两个维度选一个）

```
     快 ▲
        │  A 方案       B 方案
        │  （贵）       （又快又便宜，
        │                 但没人做过）
        │
        │  C 方案       D 方案
        │  （慢又贵）   （慢但稳）
     慢 └──────────────────────────▶
        贵                      便宜
```

用来解释「为什么不能全都要」。四个格子里最好有一个是空的或写「不存在」，
那才是重点。

## 9. 选项对比（几个方案摆一起挑）

左边一列是「用户真正在乎的问题」，不是参数名。每行都要能左右对着读。

```
             A 方案      B 方案      C 方案
改多少代码   一个文件    三个文件    重写一层
上线要多久   今天        这周        下个月
出事能回滚   能          能          不能 ← 当心
以后改起来   越来越难    还行        最省事
```

左边标签统一 5 个汉字（10 列），每个方案列宽 12 列，不够的补半角空格。
**掉头回不来的那一格，一定要用 `← 当心` 挑出来**——拍板时最该先看它。

## 10. 决策树（问自己几个问题，走到底就是答案）

```
          这批数据以后还要复用吗？
             /              \
           要                不要
            |                 |
     还得逐帧对齐吗？      选 A（今天就能上）
        /       \
      是         否
      |          |
   选 C        选 B
 （贵但稳）  （够用就行）
```

每个岔路口只问**一个用户自己答得上来的问题**——问「要不要保证时序一致性」等于没问，
要问「这批数据以后还要复用吗」。问到用户手里真有的信息为止。
