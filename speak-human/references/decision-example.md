# 完整示例：AI 抛回来的选择题 → 能拍板的样子

配合 `SKILL.md` 的「裁决结构」。和 `worked-example.md` 的区别：那边是「看不懂一段话」，
这边是「看懂了每个字，但不敢选」。两者要出的东西完全不同。

## 原话（我抛回给用户的那条）

> `paper_summary/` 下现存 412 张 PNG，合计 1.8 GB。建议统一转 lossless WebP，
> 预计压缩率约 35%。三种执行策略：(a) 原地转换并删除源文件；(b) 转换后保留 PNG
> 作为 fallback；(c) 仅对新增论文启用 WebP，存量不动。其中 (b) 会使仓库体积
> 上升约 0.6 GB。你倾向哪种？

---

## 重讲之后

**你要拍的板是：** 412 张老图要不要换成更省地方的格式；换的时候，原图删还是留。

```
             A 转完删原  B 转完留着  C 只管新的
仓库变多大   小 0.6 GB   大 0.6 GB   不变
老图还在吗   不在了      在          在（还是 PNG）
将来能反悔   不能 ← 当心 能          能
今天要多久   半小时      半小时      0（改个配置）
```

```
        这些 PNG 别处还有备份吗？
           /              \
         有               没有
          |                |
   仓库体积吃紧吗？      选 B（留着，最稳）
     /        \
   紧          不紧
    |            |
  选 A         选 B
```

**每条路通向哪：**

- **A 转完就删原图**——仓库小 0.6 GB，半小时跑完。**但原始 PNG 就没了，这是三条路里唯一掉头回不来的一条。** 转换脚本万一有毛病（某几张转坏、透明的地方变黑），你手上没有底片可以重来。`lossless WebP`（无损压缩，像素一个不差）理论上不丢东西，但「理论上」和「412 张全对」之间，隔着一次没人验过的批处理。
- **B 转完把 PNG 留着**——两份都在，随时能退（原话里的 `fallback`，就是留条退路）。代价是仓库涨 0.6 GB，以后 clone 和 CI 都慢一点。
- **C 只管新论文**——今天零成本，改个配置的事。代价是仓库里两种格式长期并存，以后写批处理脚本得多判断一次格式。

**只有你能定的是：**

- **这 412 张 PNG 在别处还有没有备份**（网盘里、或者原始 PDF 还在不在）。有备份 → A 那个「回不来」就不成立了，A 直接变成最优解。**这一条只有你答得上来，也是整件事唯一的关键。**
- 仓库现在多大、CI 拉代码慢不慢——你有体感，我只看得到数字。
- 存量图以后还会不会被重新处理（换尺寸、加水印）。会 → 留着 PNG 省事得多。

原话的倾向：我写了「建议统一转 lossless WebP」，等于已经在推 A 或 B。**但我没提「删了就没底片」这件事**，而这恰恰是 A 和 B 的全部差别。

*（我的判断，跟上面那段原话分开）*：先按 B 跑，抽查 20 张确认没问题，一周后再删 PNG。等于把 A 拆成两步，用一周的 0.6 GB，换掉那个不可逆。

> 哪一块还是糊的？点出来，我只把那一块再拆细。

---

## 这个例子做对了什么

- **「你要拍的板是」不带术语**：没有 WebP、没有压缩率，只有「换格式」和「原图删还是留」。用户读完第一行就知道自己在决定什么。
- **图是必画的，而且画了两张**：一张横着比（选项对比），一张顺着问（决策树）。前者回答「差在哪」，后者回答「那我该选哪个」——两个问题，两张图，不合并。
- **不可逆的那条单独拎出来，还说了为什么重要**：`不能 ← 当心` 在图里标了一次，正文再展开一次。只标不解释，用户不会当回事。
- **「只有你能定的是」把三条收敛到一条**：有没有备份，是唯一真正卡住这个决定的信息。裁决结构的价值就在这——不是把选项讲得更细，是**找出那个只有用户手里有的变量**。
- **原话倾向和我的判断分两行写**：挑明「我刚才其实在推 A 或 B」是翻译（原话里有的），「先 B 再删」是我的新判断（原话里没有的）。混在一起，用户就分不清哪句是他要审的、哪句是我加的。译者不是编辑，在裁决这套里就落在这个分行上。
- **最有价值的产出常常是第四条路**：原话给了 A / B / C，重讲之后冒出来的是「B 一周 → 再 A」。看懂代价结构之后，往往能拆出一个原话没列的选项。发现了就写出来，别硬塞回三选一。
